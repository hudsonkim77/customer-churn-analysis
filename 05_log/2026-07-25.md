## 3주차 프로젝트 데이 — 캠페인 데이터 정제, 대시보드 통합, 리포트 완성

### 진행 내용

**캠페인 데이터 정제** (홈 디렉토리, 위키 `raw/` 아직 미편입)
- `data_retention_campaign_raw.csv`(500행, 고객 리텐션 캠페인 로그)를 분석 → 정제규칙 협의 → 정제실행 → 결과검증 4단계로 처리
- 사용자와 6가지 판단 지점(스케일 통일, 구조적 결측 표시, 모순 행 정정 기준, 날짜역전 처리, 참조무결성 위반 처리, 완전중복 vs 근접중복)을 하나씩 상의해 확정
- `data_retention_campaign_clean.csv`(481행) 생성, `정제_규칙.md`에 [분석]·[정제규칙]·[정제실행]·[결과검증]·[통계분석가 분석리포트] 기록. 최종 6개 조건(참조무결성·스케일범위·범주값·날짜순서·모순·중복) 전수 재검증 결과 위반 0건
- 캠페인 응답 여부와 실제 이탈(`churn_yn`) 관계를 추가 분석 — 표면적 차이(89.6% vs 82.9%)는 통계적으로 유의하지 않고(p=0.059), `converted_yn` 자체가 실제 이탈과 거의 무관(p=0.50)해 측정 타당성 문제까지 확인함

**대시보드 통합**
- `app.py`의 "상담원 관점" 섹션 레이아웃을 eNPS 게이지(전체 폭) + 번아웃×CSAT·교육이수 비교(2단 컬럼)로 재정리
- `app.py` 전체를 `st.tabs(["대시보드", "개선 제안 리포트"])`로 재구성 — 기존 지표 카드·차트①~⑥·상담원 관점 섹션은 내용 변경 없이 "대시보드" 탭으로 이동, "개선 제안 리포트" 탭은 `report/고객서비스_만족도개선_리포트.md`를 읽어 프론트매터 제거 후 `st.markdown`으로 렌더링
- 로컬 실행 + Playwright로 팀 필터(전체 20명/1팀 7명/2팀 7명/3팀 6명) 전부 재검증, 탭 전환 후에도 필터 상태 유지 확인, 콘솔 에러 0건
- Streamlit Cloud 실배포본에서도 동일하게 두 탭·리포트 렌더링 확인(앱이 잠들어 있어 깨운 뒤 재확인)
